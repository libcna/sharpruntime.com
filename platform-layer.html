Platforms and portability

Platform status is reported as validation depth—not a binary supported/unsupported badge.

Evidence labels

LabelMeaning
Primary native validationThe repository’s only full native build/runtime-test baseline; read its exact outcome
Cross-compile verifiedLibrary compilation completed for a recorded toolchain; runtime tests did not run
Downstream build evidenceA consumer build drove fixes, without a standalone runtime gate
Source-supportedImplementation branches exist; this audit did not prove a complete gate
Platform-limitedSome APIs intentionally throw, reduce behavior or depend on unavailable host facilities
Compiler-limitedA compiler capability prevents part of the intended surface

Cross-platform caveats

  • Console cursor/color behavior uses ANSI sequences and is not a uniform terminal abstraction.
  • Ping and interface enumeration depend on host permissions and files; distinguish environment failures from library defects.
  • Emscripten DNS methods explicitly throw PlatformNotSupportedException.
  • Android storage’s SDL dependency must be provided by the parent build.
  • Operating-system version helpers largely report compile-time platform identity; version comparison is reduced.
No overclaim

A source path or a successful cross-compile is not described as full runtime support. Add platform CI before strengthening these labels.
